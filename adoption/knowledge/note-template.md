# Note template

Copy into `knowledge/drafts/<behavior>.md` and replace the prompts below. A few
sentences are enough; omit irrelevant fields. This template is not product truth.

- State: draft / observed / reviewed / stale / conflicted
- Behavior and scope: which feature, role and operation?
- Why this matters: what would a future engineer misunderstand?
- Product basis: requirement or decision link, including unresolved meaning
- Test evidence: file and exact test title/assertion; say what it does not cover
- Implementation: source file and symbol; date or commit checked
- Runtime evidence: sanitized artifact link, command, date and observed outcome;
  explicitly say “not executed” if no run supports this note
- Review: actual reviewer, date and review/PR reference; pending until confirmed
- Open questions/conflicts: what remains uncertain?
- Related notes: add links only when useful

Product meaning becomes active only after explicit human confirmation. Keep the
original evidence or a stable sanitized reference; a local artifact that later
vanishes cannot serve as durable provenance.
